# Train/Test Leakage And Similarity Inspection

This analysis does not train a model. It checks exact overlap, normalized overlap, template reuse, duplicate groups, and TF-IDF nearest neighbors between train and test.

## Dataset

- Train rows: `4900`
- Test rows: `2100`
- Train TRUE rows: `1400`
- Train FALSE rows: `3500`

## Exact And Normalized Cross-Set Matches

- Exact normalized train/test matched test rows: `0`
- Loose normalized train/test matched test rows: `0`
- Conservative template-key matched test rows: `0`
- Broad shape-key matched test rows: `293`

Interpretation: exact/loose matches are the strongest leakage signal. Template and shape matches are weaker because broad signatures can match unrelated samples with similar structure.

## Within-Set Duplicate Diagnostics

- Train exact duplicate groups with label conflicts: `1`
- Test exact duplicate groups: `0`

## Potential Leakage Cases

- Candidate test rows with exact/loose/template match or high TF-IDF similarity: `5`
- Nearest train label distribution among candidate rows: `{'FALSE': 4, 'TRUE': 1}`

## Practical Implication

- If exact or loose cross-set matches exist, those rows are high-risk leakage candidates and the matched train labels should be inspected manually.
- If many test rows have very high character/word TF-IDF similarity to train rows, nearest-neighbor label transfer or probability calibration may help.
- If only moderate similarity exists, this is less like direct leakage and more like repeated synthetic generation templates.
- Do not blindly override model predictions from these rules. Use the output files to inspect high-confidence cases first.
